## What the live gate actually checks

[f07d5beb](https://github.com/blaghtayt-alt/Hadith-Bank/commit/f07d5bebfdbe333e05159fa8b710495eab4ae249) requires the expected HTML SHA/source commit, validates the core index's compressed/decoded hashes/count/source/ordered-ID binding, then independently checks browser navigation on that revision. Its production smoke covers mobile Bukhari 1 results, opening an Arabic workspace, keyboard focus/back navigation, layout and accessibility-tree semantics, plus remembered wording with a transparent broader notice.

The separate live desktop benchmark measures completed cold/warm `Bukhari 1`, `actions depend on intentions`, `anger` and `controlling anger` journeys, including startup and CDP bytes, and requires expected HTML/source binding for every query. The same-host PR baseline comparison remains separate. No fixed speedup threshold is imposed; report measured outcomes without turning partial baseline searches into completed zero-result searches.

The live gate does not independently compare every remote source object, fetch every unused data part, repeat every fixture facet/export/ambiguity/corruption scenario on production, or check every external source URL. Full corpus equality belongs to build validation; requested live parts remain hash verified. Automated keyboard/ARIA/accessibility-tree checks are not a human screenreader test.
